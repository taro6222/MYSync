# WebDAV 수동 전송

저장된 동기화 쌍의 ‘검사·실행’ 버튼에서 작업 목록을 검사한 후 수동 실행한다. 자동 감시는 automatic-sync.md를 참고한다. 실행 중에는 ‘중단’을 사용할 수 있으며, 다음 검사에서 미완료 작업을 현재 상태와 대조해 재개한다.

## 지원 동작

- PROPFIND Depth:1을 재귀 호출해 폴더와 파일을 조회한다. 부분 실패·범위 밖 주소·미완료 업로드 항목은 정상 완료로 취급하지 않는다.
- 원격 파일을 임시 로컬 스트림에 내려받고 SHA-256으로 내용을 비교한다. 메모리에 전체 파일을 올리지 않는다.
- 업로드할 내용을 검증하고 원격 임시 파일에 PUT한다. 다시 다운로드해 검증한 후 MOVE로 최종 게시한다.
- 새 대상에는 Overwrite:F를 사용한다. 기존 파일에는 대상 URL에 태그된 If ETag 조건과 임시 파일의 If-Match 조건을 함께 사용한다.
- 파일 삭제는 내용을 재검사한 뒤 If-Match로 요청한다. 강한 ETag가 없으면 변경·삭제를 거부한다.
- MKCOL로 폴더를 생성한다. 원격 폴더 삭제는 하위 변경을 원자적으로 보호하는 구현이 없어 거부한다.

서버가 WebDAV 조건부 요청 의미를 준수해야 한다. RFC 4918의 MOVE·Overwrite·If 의미를 기준으로 구현했다: https://www.rfc-editor.org/rfc/rfc4918.html

## 복구 및 제한

- 원격 업로드 이름은 `.mysync-upload-`로 시작한다. 정상 게시 시 사라진다. 실패 시 내용과 ETag를 확인한 임시 파일만 조건부로 정리한다.
- 부분 업로드처럼 결과를 확정할 수 없는 파일은 임의로 지우지 않는다. 이후 검사에서 해당 경로를 오류로 표시하며 수동 확인이 필요하다.
- 원격 파일 삭제는 서버에 DELETE 요청을 보낸다. 서버 휴지통이나 버전 보존 여부는 보장하지 않는다. 로컬 교체·삭제는 기존 복구 보관함 정책을 따른다.
- 충돌 파일은 양쪽 원본과 사본을 보존하며 자동으로 한쪽을 선택하지 않는다.
- 한 쌍의 수동 실행 창은 이름 있는 Windows mutex로 중복 실행을 제한한다. 서로 다른 쌍이 같은 원격 폴더를 쓰는 경우까지 배타적으로 잠그지는 않는다.
- 회당 전체 검사와 파일별 재검사를 수행하는 초기 구현이다. 대량 파일 최적화, 이어받기, 자동 재시도 지연, 전송 속도 표시는 후속 범위다.
- HTTP 모의 서버와 실제 로컬 디스크의 왕복·수정·삭제·동시 변경·응답 유실 복구를 검증했다. 실제 사용자 WebDAV 서버와 화면 조작은 아직 검증 전이다.
