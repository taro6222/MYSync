- 계약 버전, 중복 ID, 진입 경로, 누락 어셈블리 오류 처리.
- 빌드·샘플 배치·검증·실행 스크립트.

검증 결과:

- 초기 SQLite 의존성 복원에서 탐지된 취약성을 Microsoft.Data.Sqlite 10.0.11로 갱신하여 해결.
- WPF는 컴파일 검증을 완료했으며 실제 화면 조작과 재시작 시나리오는 아직 수동 검증하지 않음.

다음 작업:

2. 2단계의 재귀 스캔, 3자 비교, 충돌 정책, 영속 작업 큐 구현.

현재 실제 클라우드 연결, 파일 전송, 트레이, 백그라운드 감시 기능은 구현 전이다. 샘플 Provider는 확장 구조를 검증하기 위한 것으로 실제 클라우드를 모사한 제품 기능이 아니다.

## 2026-09-07 — 2단계 비교·저장 계층 구현

구현:
- LocalScanner: 하위 폴더·빈 폴더를 포함한 재귀 검사, SHA-256 내용 비교, 잠금·접근 실패·링크·루트 누락 오류 보고, 취소 처리.
- SyncPlanner: 로컬·원격·기준 상태 3자 비교, 추가·수정·삭제 계획, 동시 수정·수정/삭제 충돌, 파일/폴더 충돌, 폴더 내부 변경 보호.
- 불완전한 검사나 중복·잘못된 경로는 실행 가능한 계획을 생성하지 않음.
- SyncJournal: SQLite 기준 상태·작업 저장, 조건부 작업 시작, 중단 작업의 재검사 대기 복구, 미완료 작업 중복 계획 방지.
- 양쪽 전체 상태 일치 확인 후 기준 상태와 작업 완료를 한 트랜잭션으로 반영.

검증:
- build.ps1 -Check 성공, 빌드 경고 0개·오류 0개.
- 최초 병합, 단방향 수정, 양방향 수정, 삭제, 수정/삭제 충돌, 양쪽 삭제, 폴더 내부 추가·수정 보호, 삭제 순서 검증.
- 실제 임시 폴더에서 한글 파일·빈 폴더·내용 변경·잠긴 파일·없는 루트·취소 검증.
- DB 재오픈 후 기준 상태와 예상 파일 상태 복원, 작업 이중 시작 방지, 중단 복구, 잘못된 완료 거부 검증.

남은 범위:
- 이번 구현은 계획 생성과 영속화까지이며 작업 실행기, 충돌 사본 생성, 자동 재조정·재시도는 아직 미구현.
- 로컬 스캔 결과는 파일 시스템의 원자적 스냅샷이 아니다. 실행기는 저장된 예상 상태를 실행 직전에 다시 확인해야 한다.
- 원격 스냅샷은 현재 테스트 데이터로 검증했다. Provider 인증·전송·원격 스캔 계약과 실제 서버 통합은 후속 작업이다.
- UI의 기존 설정 저장 흐름에는 아직 스캔·큐를 연결하지 않았다.
- 다음은 작업 실행기와 가짜 저장소 기반 왕복·중단 복구 검증을 마친 후 WebDAV 플러그인을 연결한다.

## 2026-09-07 — 작업 실행기와 전송 계약

구현:
- ISyncEndpoint: 전체 검사, 예상 버전 읽기, 조건부 파일 게시, 폴더 생성, 조건부 비재귀 삭제 계약.
- SyncExecutor: 각 작업 전 재검사·재계획, 예상 상태 비교, 순차 업로드·다운로드·삭제 실행, 최종 수렴 확인.
- Applied 상태를 추가해 전송 적용과 전체 동기화 완료를 구분. 완료 여부가 불확실한 작업은 재검사 후 이미 적용된 결과를 확인하고 중복 전송을 생략.
- 파일 충돌은 두 원본을 유지하고 양쪽 저장소에 안정적인 작업 ID 기반 사본을 생성. 재실행 시 같은 사본의 내용 확인 후 생략. 사용자 해결 전 NeedsReconcile 상태 유지.
- 폴더·유형 충돌은 자동 변경하지 않음.

검증:
- build.ps1 -Check 성공: 경고 0개, 오류 0개.
- 메모리 저장소 모형으로 양방향 병합·수정·하위 항목 우선 삭제·기준 상태 갱신 검증.
- 원격 게시 성공 직후 연결 실패를 주입하고 재시도 시 추가 쓰기 없이 수렴하는지 검증.
- 계획 이후 대상 변경 시 원본 보존, 충돌 양쪽 버전 보존, 재시도 사본 중복 방지 검증.

제한 및 다음 작업:
- 실제 로컬 쓰기 어댑터와 WebDAV·Google Drive 전송 어댑터는 아직 미구현이다. UI에서 실제 파일 전송을 실행하지 않는다.
- ISyncEndpoint는 엔진 측 초기 계약이며 Provider 플러그인 계약과 연결하는 작업이 남아 있다.
- 자동 재계획, 충돌 해결 UI, 재시도 지연 정책, 동기화 쌍별 실행 잠금은 후속 구현이다. 현재 실행기는 동기화 쌍당 단일 작업자 호출을 전제로 한다.
- 조건부 쓰기를 보장할 수 없는 저장소는 현재 계약을 그대로 구현한 것으로 취급할 수 없다. 실제 Provider 구현 시 기능 지원과 대체 정책을 명시해야 한다.

구현:

- 삭제 파일·빈 폴더를 같은 볼륨의 외부 복구 디렉터리에 보관.
- 지속되는 작업 의도·검증 기록과 미확인 결과의 스캔·쓰기 차단.
- 루트 경로 제한, 링크 경로 거부, Windows 예약 파일명·모호한 이름 검사.
- 동일 프로세스·동일 루트의 어댑터 쓰기 직렬화.

검증:
- build.ps1 -Check 성공: 경고 0개, 오류 0개.
- 실제 격리 폴더 두 개에서 양방향 복사, 빈 폴더, 교체, 삭제 전파 및 원본 보관 내용 확인.
- 실제 파일 충돌의 양쪽 사본과 원본 보존, 재시도 중복 생성 방지 확인.
- 해시 불일치·잘못된 경로·기존 파일 덮어쓰기·오래된 예상 상태·비어 있지 않은 폴더 삭제·취소 거부 확인.
- 미확인 복구 기록을 남긴 뒤 어댑터를 다시 생성해 차단 상태 유지 확인.

설계 보완:

- 자세한 정책과 한계는 local-recovery.md에 기록했다.

## 2026-09-07 — WebDAV 연결·탐색 플러그인

구현:
- 동일 플러그인 규격의 MYSync.Provider.WebDav DLL과 배포 설명 파일.
- 선택적 IConfigurableProvider 계약 및 공통 연결 필드·비밀번호 입력 창.
- HTTPS Basic 인증, 30초 HTTP 제한, 리디렉션 자동 이동 차단.
- PROPFIND Depth:1, DAV multistatus 처리, 한글 이름, 하위 폴더 탐색.
- 응답 항목 주소의 동일 서버·연결 루트 제한, 부분 실패·자기 항목 누락·중복·비정상 XML 거부.
- WPF 계정 연결·선택 폴더 열기·연결 루트로 이동 및 빌드 시 플러그인 배치.

검증:
- build.ps1 -Check 통과. 모의 HTTP 핸들러에서 인증 헤더·요청 메서드·Depth·폴더 탐색과 오류 거부 검증.
- 실제 플러그인 로더에서 샘플과 WebDAV 동시 로드 확인.
- 실제 사용자 WebDAV 서버와 화면 조작은 아직 검증하지 않았다.

현재 범위:
- 연결 정보는 메모리에만 유지한다. 비밀번호를 설정 DB나 설명 파일에 저장하지 않는다.
- 계정 영속 저장 전에는 WebDAV 동기화 쌍 저장을 막는다. 기존 샘플 설정 저장은 유지한다.
- 읽기·탐색 단계이며 업로드·다운로드·삭제와 엔진 연결은 아직 미구현이다.
- 다음은 계정 ID·비밀 저장소와 WebDAV 전송 어댑터 구현이다.

참고: RFC 4918 https://www.rfc-editor.org/rfc/rfc4918.html — PROPFIND와 multistatus 의미에 따라 구현했다.
