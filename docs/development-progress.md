## 2026-09-07 — 작업 실행기와 전송 계약

구현:
- ISyncEndpoint: 전체 검사, 예상 버전 읽기, 조건부 파일 게시, 폴더 생성, 조건부 비재귀 삭제 계약.
- SyncExecutor: 각 작업 전 재검사·재계획, 예상 상태 비교, 순차 업로드·다운로드·삭제 실행, 최종 수렴 확인.
- Applied 상태를 추가해 전송 적용과 전체 동기화 완료를 구분. 완료 여부가 불확실한 작업은 재검사 후 이미 적용된 결과를 확인하고 중복 전송을 생략.
- 파일 충돌은 두 원본을 유지하고 양쪽 저장소에 안정적인 작업 ID 기반 사본을 생성. 재실행 시 같은 사본의 내용 확인 후 생략. 사용자 해결 전 NeedsReconcile 상태 유지.
- 폴더·유형 충돌은 자동 변경하지 않음.

검증:
- build.ps1 -Check 성공: 경고 0개, 오류 0개.
- 메모리 저장소 모형으로 양방향 병합·수정·하위 항목 우선 삭제·기준 상태 갱신 검증.
- 원격 게시 성공 직후 연결 실패를 주입하고 재시도 시 추가 쓰기 없이 수렴하는지 검증.
- 계획 이후 대상 변경 시 원본 보존, 충돌 양쪽 버전 보존, 재시도 사본 중복 방지 검증.

제한 및 다음 작업:
- 실제 로컬 쓰기 어댑터와 WebDAV·Google Drive 전송 어댑터는 아직 미구현이다. UI에서 실제 파일 전송을 실행하지 않는다.
- ISyncEndpoint는 엔진 측 초기 계약이며 Provider 플러그인 계약과 연결하는 작업이 남아 있다.
- 자동 재계획, 충돌 해결 UI, 재시도 지연 정책, 동기화 쌍별 실행 잠금은 후속 구현이다. 현재 실행기는 동기화 쌍당 단일 작업자 호출을 전제로 한다.
- 조건부 쓰기를 보장할 수 없는 저장소는 현재 계약을 그대로 구현한 것으로 취급할 수 없다. 실제 Provider 구현 시 기능 지원과 대체 정책을 명시해야 한다.

## 2026-09-07 — 자동 감시·일시정지

- SyncMonitor에 로컬 변경 감지, 이벤트 병합, 5분 재검사, 순차 실행, 취소 기능 구현.

## 2026-09-07 — 충돌·복구 확인 화면

구현:
- RecoveryStore: 복구 기록을 조회 시점의 대상·보관본 해시로 다시 판정(적용됨·적용 안 됨·판정 불가), 동기화 폴더 밖으로만 보관본 복원, 확인 처리 시 기록과 보관본을 resolved 폴더로 이동하고 확인 이력 기록.
- SyncJournal.ResolveConflict: 사용자가 선택한 쪽의 반대편 현재 상태를 기준 상태에 기록해 기존 3자 비교가 전송을 계산하도록 함. 결정 전후 계획을 비교해 다른 경로의 작업이 바뀌면 중단하고, 기준 상태 갱신·충돌 작업 완료·새 작업 등록을 한 트랜잭션으로 반영.
- ResolveWindow: 미해결 작업과 보존 사본 표시, 연결·현재 상태 검사, 로컬/원격 우선 결정, 복구 기록 조회·복원·확인 처리. 수동 실행 창과 같은 쌍 단위 잠금 사용.
- 동기화 목록에 ‘충돌·복구’ 버튼 추가와 창 생성 경로 공통화.

검증:
- 빌드 성공: 경고 0개, 오류 0개. 전체 자동 검증 통과.
- 적용된 교체 기록의 판정과 해시 확인, 동기화 폴더·복구 보관함 안으로의 복원 거부, 덮어쓰지 않는 재복원.
- 확인 처리 후 기록 이동·보관본 유지·재처리 거부, 중단된 기록의 적용 안 됨/판정 불가 분류, 판정 불가의 검토 요구, 확인 처리 후 스캔 차단 해제.
- 조회 이후 대상이 바뀐 기록의 복원·확인 처리 거부.
- 실제 디스크 충돌에서 로컬 우선 결정 후 Upload 재계획, 수렴, 양쪽 충돌 사본 유지, 버려진 원격 내용의 보관 확인. 불완전한 검사와 같은 충돌의 중복 해결은 거부.
