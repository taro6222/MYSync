# 실패 기록과 진단 로그

2026-09-08 구현. Synology ETag 호환성 수정에 앞서 실제 실패 근거를 남기기 위한 단계다.

- `%LOCALAPPDATA%/MYSync/logs/sync-YYYY-MM-DD.jsonl`에 UTC 시각, 이벤트, 동기화 쌍 ID, 작업 ID, HTTP 메서드·상태 코드·강한 응답 헤더 ETag 유무, 오류 분류·예외 타입을 기록한다.
- 작업 실행의 비동기 호출 흐름에는 쌍·작업 ID가 전파된다. 계정 연결이나 작업 밖 검사는 ID가 없을 수 있다.
- URL·계정 값·인증 헤더·응답 본문·예외 메시지는 파일 로그에 넣지 않는다. PROPFIND XML 내부의 getetag 값은 이 로그의 ETag 유무에 포함되지 않는다.
- 파일 로그는 하루 약 10 MiB에서 기록을 멈춘다. 날짜별 파일은 자동 삭제하지 않는다. 디스크 부족·접근 거부로 로그를 쓰지 못해도 파일 전송 결과를 바꾸지 않는다. 로그 쓰기 실패를 표시하는 UI는 아직 없다.

작업 DB의 Jobs에는 마지막 실패 사유 `FailureReason`, 분류 `FailureKind`, UTC 시각 `FailedAt`을 저장한다. 기존 DB에는 nullable 열을 추가하며 기존 작업과 기준 상태를 보존한다. 작업 상태와 실패 정보를 같은 UPDATE로 기록한다. 재시도 성공 시 이전 오류를 비우며 취소·충돌도 사유를 남긴다. 개별 재시도의 분류는 파일 로그에 남고 DB에는 마지막 작업 결과만 남는다.

실패 사유는 ‘충돌·복구’의 미해결 작업 목록에서 재연결 없이 확인할 수 있다. ‘검사·실행’에서는 검사에 성공해 기존 작업을 표시할 때 사유를 보여준다. DB 사유에는 상대 파일 경로 등 사용자 데이터가 포함될 수 있으므로 사용자 DB 전체를 보고 자료로 공유하지 않는다. Provider는 오류 메시지에 자격 증명을 포함하지 않아야 한다.

검증: 구형 Jobs 테이블 마이그레이션·재오픈·실패 복원·성공 시 해제, 실제 실행기의 최종 오류 저장, HTTP 401 로그와 작업 ID 연계, 연결 값 미노출, 로그 경로 쓰기 실패 격리를 자동 검증했다. 테스트 로그는 `.tools/checks`에 격리한다.

Synology GET ETag 누락과 원격 잔류 업로드 정리는 아직 수정하지 않았다. 기존 원격 파일에 변경을 가하거나 사용자 DB를 정리하지 않았다.
