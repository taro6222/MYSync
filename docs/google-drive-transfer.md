# Google Drive 전송 1차 구현

2026-09-08. 사용자가 실제 Google 로그인과 폴더 탐색 성공을 확인한 뒤 재귀 검사·파일 전송을 연결했다. 전송은 모의 API와 실제 로컬 폴더로 검증했으며 실제 Google 전송 테스트는 아직 남아 있다.

## 사용 순서

1. Google Cloud의 OAuth 데이터 액세스에 `https://www.googleapis.com/auth/drive`를 추가한다. 배포용 클라이언트는 기존 것을 사용한다.
2. 새 MYSync에서 저장 계정을 선택하고 **Google 다시 로그인**을 눌러 파일 관리 권한을 승인한다. 기존 읽기 전용 토큰은 전송 계정으로 사용하지 않는다.
3. 테스트용 로컬·원격 폴더를 선택해 동기화 쌍을 저장한다. **검사·실행**으로 계획을 확인한 뒤 실행한다. 이후 자동 시작도 사용할 수 있다.
4. 최초 업·다운로드, 빈 폴더·한글 이름, 수정, 파일 삭제, 동시 수정, 중단 후 재개를 테스트한다.

권한은 선택 폴더만이 아니라 Drive 파일 관리 범위다. [Google Drive 범위 안내](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)를 참고한다.

## 전송과 검사

- 파일 ID로 내용을 읽고, 상대 경로는 상위 폴더 ID를 따라 목록을 조회해 해석한다. 페이지 조회 실패·불완전 검색·중복 ID·잘못된 부모는 검사 오류로 전체를 막는다.
- 바이너리 파일을 임시 파일에 내려받아 SHA-256을 계산한다. 다운로드 전후 메타데이터 버전·부모·이름·유형이 같아야 한다. 임시 파일은 스트림 종료 시 삭제한다.
- 첫 버전은 **5 MiB 이하 파일**만 전송한다. 큰 원격 파일은 미지원으로 보고한다. 큰 로컬 파일 업로드는 원격 쓰기 전에 거부하고 미완료 작업으로 남긴다.
- 새 파일·폴더 ID는 generateIds로 얻어 생성 요청에 사용한다. 업로드는 multipart 요청이며 게시 후 ID와 내용 해시를 재확인한다. 성공 응답 유실은 기존 실행기의 재검사로 이미 적용된 결과를 확인한다.
- 기존 파일 교체와 파일 휴지통 이동은 실물을 다시 내려받아 예상 해시와 버전을 확인하고, 메타데이터의 강한 ETag를 If-Match에 사용한다. ETag가 없으면 해당 변경을 거부한다. API 응답과 검사 결과를 로그에 기록한다.
- 파일 삭제는 영구 DELETE가 아니라 `trashed:true` 갱신이다. 원격 폴더 삭제는 하위의 동시 변경을 보호할 수 없어 거부한다.

Google은 같은 이름의 파일을 허용한다. 동일 폴더의 중복 이름(대소문자 차이 포함)은 해당 경로와 하위를 미지원으로 표시해 보존한다. 생성 요청과 이름 확인을 원자적으로 묶지는 못하므로 외부에서 동시에 생성하면 중복이 남을 수 있다. 게시 후 재조회에서 이를 오류로 보고하고 임의 정리하지 않는다. 멀티파트 전송의 재개·영속 업로드 세션은 아직 없다.

Google 문서·바로가기·공유 드라이브는 미지원으로 보고한다. 큰 파일의 이어받기, 변경 커서, 원격 해시 캐시, 병렬 전송은 후속 범위다. 폴더 이동과 파일 작업 전체를 하나의 트랜잭션으로 묶는 보장은 없다.

## 검증과 한계

전체 `build.ps1 -Check` 통과, 경고·오류 0개. GoogleTransferChecks는 재귀 실제 디스크 왕복·교체·휴지통, 동시 수정의 조건부 요청 거부, 강한 ETag 누락 거부, 폴더 삭제 차단, 중복 이름·Google 문서 보고, 불완전 검색, 크기 제한, 응답 유실 후 업로드 중복 방지를 검증한다. 기존 읽기 전용 계정의 재동의 요구도 확인한다.

**실제 Drive의 ETag 제공 및 조건부 변경 집행은 아직 확인하지 않았다.** 모형 검증을 실서버 호환성 보장으로 해석하지 않는다. 실패 시 `googledrive.response` 로그와 작업의 저장된 실패 사유를 확인한다. 사용자 Google 파일에 대한 개발 도구 전송·삭제는 수행하지 않았다.
