# 전송·검증 성능 개선 (2026-09-08)

## 동작

- 파일의 전송·내용 검증이 끝나면 즉시 완료 이벤트를 표시한다. 다른 파일이나 마지막 전체 비교를 기다리지 않는다. 이 시점의 완료는 해당 버전의 파일 처리 완료이며, 전체 연결의 최신 상태 수렴은 별도로 판정한다.
- 전체 폴더 비교는 하단 상태에 따로 표시한다. 영속 작업은 Applied 상태로 남아 재시작 시 재검사하며, 비교 기준과 Completed 확정은 기존 체크포인트 절차를 유지한다.
- Google 개별 검사·교체 전 검증·게시 후 검증에 서버 SHA256을 사용한다. 해당 경로를 확인하고 최신 메타데이터의 ID·버전·이름·유형·크기·상위 폴더를 확인한다. 교체·휴지통의 ETag 조건부 요청도 유지한다.
- SHA256이 없는 파일은 다운로드 검증 결과를 버전에 묶어 메모리에 보관한다. 최대 10,000개, 5분이며 새 버전·이동·이름·크기 등이 다르면 재사용하지 않는다. 시간만으로 쓰기를 허용하지 않고, 최신 서버 메타데이터를 확인한 뒤 검증 결과를 재사용한다.
- 실제 다운로드(OpenRead)는 캐시 여부와 관계없이 내용을 받는다. 캐시는 파일 내용 대신 사용할 수 없다. 다운로드·업로드 준비 과정에서 바이트를 읽으며 해시를 계산해 임시 파일을 해시 계산용으로 다시 읽는 비용을 줄였다.
- Google 폴더 목록과 체크섬이 없는 항목 검사를 최대 3개씩 병렬 처리한다. 로컬·원격 전체 검사도 함께 실행한다.
- 자동 실행은 방금 얻은 계획용 전체 검사 결과를 실행기에 전달해 중복 검사를 없앤다. 파일별 실행 직전 확인과 폴더 변경의 새 구조 검사는 유지한다.
- 로그 한도에 도달하면 오래된 기록을 약 25% 단위로 정리한다. 한도가 찬 뒤 HTTP 응답 한 건마다 전체 로그를 다시 복사하던 비용을 줄인다. 최대 크기는 계속 준수하며 최신 기록을 보관한다.

## 검증 결과

모의 Google 서버에 64 KiB 파일 8개를 두고 최초 검사, 전체 검사 3회 반복, 파일별 확인, 8개 덮어쓰기, 마지막 검사를 수행했다.

| 서버 체크섬 | 해당 시나리오의 검증용 미디어 GET |
| --- | --- |
| SHA256 제공 | 0건 |
| SHA256 없음 | 16건: 최초 버전 8개 + 변경 후 버전 8개 |

추가로 서버에서 버전을 변경하면 새 해시를 확인하고, 이전 내용 기준의 덮어쓰기를 거부하는 것을 검증했다. 실제 OpenRead에는 다운로드 요청이 발생한다.

지연시킨 전송과 마지막 전체 검사 앞에서 완료 이벤트를 관찰해 빠른 파일이 먼저 완료되고, 계획 검사 결과가 반복되지 않는 것을 검증했다. 오래된 계획을 재사용해도 실행 직전 달라진 파일의 쓰기는 거부했다. 로그 압축 후 여유 공간과 다음 기록의 단순 추가도 검증한다.

이는 자동화된 요청 수·정합성 검증이다. 실제 Google 계정의 전송 시간이나 배속을 측정한 결과는 아니다. 실서버 목록 조회·네트워크 대역폭·서버 제한·로컬 해시 비용은 여전히 발생한다. 체크섬이 없는 파일은 최초 검사와 캐시 만료 시 다운로드가 필요하다. Google 변경 피드 기반의 증분 목록 수집은 아직 적용하지 않았다.

## API 근거

Google은 [File 메타데이터](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)에 SHA256(제공 가능한 경우)과 모든 서버 변경을 반영하는 증가 버전을 제공한다. 이 정보가 부족하거나 실제 내용과 일치하지 않으면 기존 다운로드·무결성 검증으로 처리하거나 변경을 거부한다.
