# 오류 분류·재시도와 검사 비용

## 오류 분류

Provider는 실패를 문구가 아니라 분류와 함께 던진다. `SyncTransferException`은 `SyncFailureKind`를 가지며, 엔진은 이 값만 보고 재시도 여부를 정한다.

| 분류 | 의미 | 예 | 자동 재시도 |
| --- | --- | --- | --- |
| Transient | 잠시 후 사라질 수 있는 상태 | 408, 423, 429, 503, 그 외 5xx, 네트워크 오류, 요청 시간 초과 | 함 |
| Authentication | 인증 거부 | 401 | 안 함 |
| Permission | 권한 거부 | 403 | 안 함 |
| Missing | 항목 없음 | 404, 410 | 안 함 |
| Precondition | 상태가 예상과 다름 | 412, 409, 405, 계획 이후 변경 | 안 함 |
| Unknown | 분류할 수 없음 | 507, 그 외 | 안 함 |

507(저장 공간 부족)은 시간이 지나도 저절로 해결되지 않으므로 일시 장애로 취급하지 않는다. 분류할 수 없는 상태도 재시도하지 않는다.

## 재시도

- 작업 단위로 최대 3회 시도한다. 지연은 2초에서 시작해 두 배씩 늘고 30초에서 멈춘다.
- **재시도는 같은 요청을 반복하지 않는다.** 매 시도마다 로컬·원격을 다시 검사하고 계획을 다시 세운 뒤, 예상 상태가 일치할 때만 실행한다. 이전 시도가 실제로는 성공했다면 재검사에서 확인하고 전송을 생략한다.
- 사용자가 중단하면 재시도하지 않는다. 요청 시간 초과로 인한 취소는 사용자 중단과 구분해 일시 장애로 다룬다.
- 실행 결과에는 남은 실패가 전부 일시 장애인지(`TransientOnly`)를 함께 담는다.
- 자동 감시는 실패가 전부 일시 장애일 때만 다음 검사를 다시 예약한다. 기본 5회까지이며, 그 다음에는 감시를 멈추고 확인을 요청한다. 충돌·인증·권한 실패는 즉시 멈춘다.
- 실패 항목은 분류 이름을 붙여 표시한다. 예: `보고서.docx: [권한] 서버가 접근을 거부했습니다.`

## 검사 비용

초기 구현은 검사할 때마다 로컬 전체를 해시하고 원격 파일을 전부 내려받아 해시했다. 실행기가 작업마다 재검사하므로 비용이 작업 수에 비례해 늘었다. 두 가지 캐시를 추가했다.

**로컬 지문 캐시** — 파일 경로별로 길이·마지막 쓰기 시각·해시·검증 시각을 기억한다. 길이와 시각이 같고 마지막 해시 검사 후 5분 미만일 때만 재사용한다. 만료 후 다음 검사에서는 다시 해시하며, 캐시 적중으로 만료 시각을 연장하지 않는다. 시스템 시각이 검증 시각보다 과거가 되어도 다시 해시한다. 정상 전체 검사 후 사라진 경로를 캐시에서 정리하며 실패·취소 시에는 정리하지 않는다. LocalEndpoint 인스턴스 안에서만 유지하며 디스크에 저장하지 않는다.

**원격 ETag 캐시** — 강한 ETag와 길이가 직전에 해시한 값과 같으면 다시 내려받지 않는다. 약한 ETag는 캐시하지 않는다. 실제 GET 헤더의 ETag 또는 If-Match GET으로 확인한 PROPFIND ETag를 사용한다. 업로드·삭제에 성공하면 해당 항목의 캐시를 즉시 비운다. 세션 메모리에만 유지한다. [ETag 호환성 보완](webdav-etag.md)을 참고한다.

### 왜 안전한가

두 캐시는 **계획 단계에만 영향을 준다.** 실제로 파일을 바꾸거나 지우기 직전에는 캐시를 쓰지 않고 항상 실물을 다시 확인한다.

- 로컬: `PutFileAsync`·`DeleteAsync`는 대상 파일을 직접 해시해 예상 상태와 비교하고, 다르면 거부한다. 읽기도 스트림 해시를 확인한다.
- 원격: 교체·삭제 전에 대상을 내려받아 해시를 비교하고 강한 ETag로 조건부 요청을 보낸다.

따라서 캐시가 낡으면 **변경 감지가 한 주기 늦어질 수는 있어도, 잘못된 내용에 대해 쓰기나 삭제가 실행되지는 않는다.**

### 남는 한계

로컬에서 길이와 수정 시각이 유지된 변경은 캐시 만료 후 다음 검사에서 감지한다. 만료 자체가 검사를 예약하지 않으므로 감지 시점은 자동 검사 주기와 실행 시간에도 달려 있다. 원격 서버가 내용 변경에도 강한 ETag를 유지하는 경우의 캐시 한계는 남아 있다. 작업 직전 실물 재확인 정책은 유지한다.

전송 이어받기, 변경 블록만 전송, 병렬 전송, 검사 결과의 디스크 캐시는 아직 없다.

## 검증

상태별 분류, 상한이 있는 지수 지연, 일시 장애만 재시도하고 정책 횟수를 지키는지, 영구 오류를 재시도하지 않고 분류 이름을 붙이는지, 감시가 일시 장애를 정해진 횟수까지만 재시도하는지, 로컬 캐시가 재사용·무효화되고 낡은 값으로는 삭제가 거부되는지, 원격 캐시가 강한 ETag에만 적용되고 약한 ETag에는 적용되지 않는지를 자동 검증했다.
