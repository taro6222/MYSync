# 로컬 파일 처리와 복구

## 저장 위치

LocalEndpoint 생성 시 기존 동기화 루트와 별도의 복구 디렉터리를 지정한다. 두 디렉터리는 서로 포함할 수 없으며 같은 볼륨에 있어야 한다. 실제 다중 동기화 쌍을 연결할 때 복구 디렉터리가 다른 동기화 쌍에도 포함되지 않는지 호스트가 검사해야 한다.

## 파일 전송

1. 복구 디렉터리의 임시 파일에 데이터를 기록하고 디스크에 플러시한다.
2. SHA-256 해시를 검증한다.
3. 대상 경로와 예상 내용을 재검사한다.
4. 신규 파일은 덮어쓰기 없는 이동으로 게시한다.
5. 기존 파일은 복구 의도를 먼저 기록한 후 File.Replace로 교체하며 실제 교체된 원본을 보관한다.
6. 보관된 원본 해시가 예상 상태와 일치해야 복구 기록을 검증 완료로 표시한다.

파일을 읽는 동안 쓰기·삭제 공유를 허용하지 않으며, 스트림 해시를 확인한 후 호출자에게 반환한다. 링크·정션, 상위 경로 이동, Windows 장치명, 끝의 점·공백 등 모호한 경로는 거부한다. 검사 단계에서는 이런 항목을 오류가 아니라 미지원 항목으로 보고해 나머지 동기화를 막지 않는다. [미지원 항목 처리](unsupported-items.md)를 참고한다.

## 삭제

파일 삭제는 복구 디렉터리로 이동한 후 내용 검증을 수행한다. 폴더는 비어 있는 경우에만 이동하며 이동 후에도 비었는지 확인한다. 하위 항목을 재귀적으로 파기하지 않는다. 복구 디렉터리는 자동 삭제하지 않는다.

## 복구 기록

각 작업은 `.json` 기록과 `.original` 파일 또는 폴더를 남긴다. 기록에는 원래 루트, 상대 경로, 동작, 예상 상태, 보관 경로, 검증 완료 여부가 들어 있다.

`Verified=false`는 결과를 확정하지 못했다는 뜻이며 실제 파일 작업이 실행되지 않았을 수도 있다. 작업 전 의도 기록 이후 종료되거나 작업 중 오류가 발생하면 이 상태가 남을 수 있다. 어댑터 재생성 후에도 미확인 기록이 있으면 추가 쓰기와 정상 스캔을 차단한다.

앱의 ‘충돌·복구’ 화면에서 기록을 조회하고, 보관본을 동기화 폴더 밖으로 복원하고, 확인 처리할 수 있다. 판정은 저장된 Verified 값이 아니라 조회 시점의 대상·보관본 해시로 다시 계산한다. 확인 처리는 기록과 보관본을 `resolved` 하위 폴더로 옮기고 확인 이력을 남긴 뒤에만 차단을 해제한다. 판정할 수 없는 기록은 사용자가 직접 비교했음을 선택해야 처리된다. 자세한 절차는 [충돌·복구 확인](conflict-recovery.md)을 참고한다.

기록을 직접 삭제하거나 Verified 값을 손으로 바꾸면 안 된다. 자동 복원 도구는 아직 없으며, 현재 복원 기능은 보관본을 별도 위치로 복사할 뿐 원래 위치를 덮어쓰지 않는다.

## 보장 범위

Windows 경로 기반 파일 API는 외부 프로그램의 변경과 내용 비교·교체를 하나의 조건부 연산으로 처리하지 않는다. 이 구현은 교체 직전 검사와 실제 교체된 원본의 보존·사후 검증으로 대응한다. 뒤늦은 변경을 발견하면 미확인 상태로 중단하며, 보관본을 버리지 않는다. 자동 롤백으로 새 파일을 다시 덮어쓰지 않는다.

악의적인 프로세스의 동시 경로·링크 교체까지 막는 보안 경계는 아니다. 동일 프로세스의 같은 루트에 대한 어댑터 쓰기는 직렬화하지만, 여러 앱 프로세스 실행 방지와 동기화 쌍 전체 실행 잠금은 호스트 통합 시 추가해야 한다.

현재 실제 Windows 디스크에서 정상 전송·원본 보관·충돌 사본·취소·해시 오류·오래된 예상 상태 거부를 검증했다. 전원 손실 실험, 임의의 파일 시스템, 외부 프로세스와의 경쟁 상황 전체를 검증한 것은 아니다.
