# 충돌·복구 확인

동기화 목록의 ‘충돌·복구’ 버튼에서 미해결 작업과 복구 기록을 확인하고 처리한다. 자동 감시 중인 쌍은 먼저 일시정지해야 하며, 수동 실행 창과 같은 쌍 단위 Windows mutex로 중복 실행을 막는다.

## 미해결 작업과 충돌 해결

- 완료되지 않은 작업의 상태·종류·경로·이유와, 충돌로 보존된 사본의 이름을 표시한다.
- ‘연결·현재 상태 검사’는 저장 계정으로 연결한 뒤 로컬·원격을 전체 검사한다. 어느 한쪽이라도 검사가 불완전하면 해결을 진행하지 않는다.
- 파일 충돌만 ‘로컬 파일 우선’ 또는 ‘원격 파일 우선’으로 결정할 수 있다. 폴더·유형 충돌과 대소문자 경로 충돌은 이 화면에서 처리하지 않는다.
- 해결은 별도의 전송 경로를 만들지 않는다. 버리기로 한 쪽의 현재 상태를 기준 상태에 기록해, 기존 3자 비교가 Upload·Download·DeleteLocal·DeleteRemote를 스스로 계산하게 한다.
- 기록 전에 해결 전후 계획을 비교한다. 선택한 경로 외의 작업이 하나라도 달라지면 중단한다. 계산된 작업이 선택한 방향과 다르면 역시 중단한다.
- 검사 이후 해당 항목이 변경되었으면 거부한다. 결정은 기준 상태 갱신, 충돌 작업 완료 처리, 새 작업 등록을 한 트랜잭션으로 반영한다.
- 양쪽에 보존된 충돌 사본은 지우지 않는다. 결정 후 ‘검사·실행’ 창에서 재개하면 실제 전송이 실행된다.

## 복구 기록

- 기록에 저장된 `Verified` 값을 신뢰하지 않고, 조회할 때마다 대상과 보관본을 다시 해시해 판정한다.
  - **적용됨 · 원본 보관**: 보관본이 예상 내용과 일치한다. 작업이 적용되었고 이전 내용이 보존되어 있다.
  - **적용 안 됨 · 대상 유지**: 보관본이 없고 대상이 예상 내용 그대로다. 작업이 실행되지 않았다.
  - **판정 불가**: 그 외. 작업 직전 외부에서 변경된 내용을 보관했거나, 보관본과 대상이 모두 예상과 다른 경우다.
- ‘보관본을 다른 위치로 복원’은 동기화 폴더와 복구 보관함 밖으로만 복사한다. 기존 파일을 덮어쓰지 않고 이름을 바꿔 저장하며 복사 후 해시를 확인한다. 원래 위치로 되돌리지 않는다.
- ‘확인 처리’는 기록과 보관본을 삭제하지 않는다. `resolved` 하위 폴더로 옮기고 판정·처리 시각·직접 확인 여부를 담은 확인 기록을 남긴다. 이 처리 후에야 해당 기록의 스캔·쓰기 차단이 풀린다.
- 판정 불가 기록은 ‘보관본과 현재 대상을 직접 비교했습니다’를 선택하지 않으면 확인 처리를 거부한다.
- 조회 이후 대상이나 보관본이 바뀌면 복원과 확인 처리를 모두 거부한다. 다시 조회해야 한다.

## 검증 및 제한

실제 디스크에서 적용된 교체 기록의 판정, 동기화 폴더 밖 복원과 덮어쓰기 방지, 확인 처리 후 보관본 유지와 재처리 거부, 중단된 기록의 분류와 검토 요구, 확인 처리 후 스캔 차단 해제, 조회 이후 변경 거부, 충돌 결정의 재계획·수렴·양쪽 버전 보존을 자동 검증했다.

`resolved` 폴더는 자동으로 비우지 않는다. 보관본 정리는 사용자가 직접 판단한다. 자동 복원 도구는 없다. 실제 화면 조작 검증은 수동 테스트 범위이며 [manual-test.md](manual-test.md)를 따른다. 세부 보존 정책은 [로컬 복구](local-recovery.md)를 확인한다.
