# Windows 파일 동기화 프로그램 개발 계획서

- 작성일: 2026-09-07
- 상태: 초기 개발 계획
- 대상 플랫폼: Windows
- 지원 원격 저장소: WebDAV, Google Drive

## 1. 목표

MEGAsync와 같은 폴더 동기화 경험을 제공하는 Windows 데스크톱 프로그램을 개발한다. 사용자가 로컬 폴더와 원격 폴더를 선택하면 두 폴더를 동기화 쌍으로 연결하고, 내부 파일과 하위 폴더를 상대 경로 기준으로 양방향 동기화한다.

기존 대화의 `wevdev`는 WebDAV로 해석했다. 자체 클라우드 서버를 구축하는 것이 아니라 사용자의 WebDAV 서버와 Google Drive에 직접 연결한다.

예시:

```text
로컬: D:\Documents
원격: Google Drive / Documents

D:\Documents\업무\보고서.docx
                ↕
Google Drive / Documents / 업무 / 보고서.docx
```

## 2. 확정 요구사항과 기본 설계안

### 확정 요구사항

- Windows에서 실행한다.
- WebDAV와 Google Drive를 지원한다.
- Provider를 DLL 플러그인으로 추가할 수 있도록 설계한다. 초기 두 Provider도 같은 플러그인 규격으로 구현한다.
- 사용자가 로컬 폴더와 원격 폴더를 선택한다.
- 선택한 폴더 내부의 모든 파일과 하위 폴더를 동기화 대상으로 한다.

### 대화에 기반한 기본 설계안

- 양방향 동기화를 기본으로 한다.
- 하나의 동기화 쌍은 로컬 폴더 하나와 원격 폴더 하나를 연결한다.
- 최초 연결에서는 양쪽 항목을 병합하고, 이후에는 마지막 동기화 상태를 기준으로 추가·수정·삭제를 판정한다.
- 동시 수정과 최초 연결의 내용 충돌은 두 버전을 보존한다.
- 창을 닫아도 트레이에서 실행하며, 일시정지·재개·진행 상태 확인을 제공한다.
- 로그인 시 자동 실행을 설정할 수 있도록 한다.

기본 설계안은 구현 기준으로 제안한 정책이며, 모든 세부 동작이 사용자에 의해 개별 확정된 것은 아니다.

## 3. 기술 스택

| 영역 | 선택 | 용도 |
|---|---|---|
| 언어·런타임 | C# / .NET 10 LTS | 파일 처리, 비동기 작업, Windows 연동 |
| UI | WPF + MVVM | 설정, 원격 폴더 탐색, 전송 목록, 트레이 |
| 동기화 엔진 | 독립 C# 클래스 라이브러리 | 비교·계획·실행 로직 분리 |
| 플러그인 | Provider.Abstractions + PluginHost | 공통 계약과 플러그인 검색·검증·로드 |
| 로컬 DB | SQLite / Microsoft.Data.Sqlite | 동기화 기준 상태와 영속 작업 큐 |
| 파일 감지 | FileSystemWatcher + 재검사 | 변경 신호 수집과 누락 복구 |
| 작업 실행 | System.Threading.Channels + async/await | 제한된 동시 실행과 취소 처리 |
| WebDAV | HttpClient 기반 Provider | 목록 조회와 파일 작업 |
| Google Drive | Google Drive API 클라이언트 | OAuth 인증, 파일 작업, 변경 추적 |
| 자격 증명 | Windows 보안 저장소 | 계정 비밀·토큰 보호 |

PostgreSQL, ASP.NET Core 서버, 자체 객체 스토리지는 현재 범위에 필요하지 않다. 실제 패키지 버전과 배포 도구는 구현 시작 시 호환성을 확인해 고정한다.

## 4. 구성 및 책임

```text
WPF UI / 트레이
       │
공통 동기화 엔진 ── SQLite
       │
Provider.Abstractions / PluginHost
       ├─ plugins/WebDAV/
       ├─ plugins/GoogleDrive/
       └─ plugins/추가 Provider/
```

| 구성 요소 | 책임 |
|---|---|
| Desktop | 계정 연결, 폴더 선택, 상태 표시, 사용자 명령 |
| Sync.Core | 로컬·원격·기준 상태 비교, 충돌 판정, 실행 계획 |
| Sync.Infrastructure | 로컬 파일 작업, DB, 영속 큐, 재시도, 로그 |
| Provider.Abstractions | 버전이 있는 공통 인터페이스, 데이터 형식, 기능 지원 선언 |
| PluginHost | 설명 파일 검사, 호환성 검증, 로드, Provider 등록과 오류 표시 |
| Providers.WebDav | WebDAV 인증·경로·서버 응답 처리 |
| Providers.GoogleDrive | Google 인증·파일 ID·변경 커서 처리 |
| Tests | 엔진 정책, Provider 계약, 복구 시나리오 검증 |

첫 버전은 사용자 세션의 트레이 앱에서 엔진을 구동한다. 로그아웃 중 실행을 위한 Windows Service는 후속 범위로 둔다.

Provider는 목록 조회, 메타데이터 조회, 다운로드, 업로드, 폴더 생성, 이동·이름 변경, 삭제를 제공한다. 변경 추적, 조건부 갱신, 이어받기 등은 지원 여부를 명시하도록 한다. 서비스별 기능 차이를 공통 인터페이스에서 숨겨 잘못된 보장을 하지 않는다.

### 4.1. Provider 플러그인 계약

공통 엔진과 UI는 구체적인 Provider 구현을 직접 참조하지 않는다. 공통 계약을 만족하는 새 Provider는 엔진 수정이나 재빌드 없이 배포 폴더에 추가할 수 있도록 한다. 기존 계약으로 표현할 수 없는 새 기능은 계약의 호환성 정책에 따라 확장한다.

- Provider 고유 ID, 표시명, 버전과 지원 기능을 제공한다.
- 계정 연결, 연결 해제, 인증 갱신, 원격 폴더 탐색과 기본 파일 작업을 계약에 포함한다.
- 주소·계정 입력 등은 선언형 설정 항목으로 표현하고, OAuth는 호스트가 제공하는 브라우저 인증 흐름과 연계한다. 특정 Provider 추가 때문에 UI를 수정하지 않도록 한다.
- 원격 항목 ID, 부모 ID, 이름, 표시 경로, 버전 토큰을 분리한다. 경로가 식별자인 저장소와 별도 파일 ID가 있는 저장소를 모두 표현한다.
- 변경 추적, 조건부 갱신, 이어받기, 서버 측 이동 등은 기능 지원 선언으로 구분한다. 미지원 기능에는 재검사·파일 단위 재전송 등 명시적인 대체 동작을 적용한다.
- 비동기 작업, 취소, 전송 진행률과 오류 분류를 통일한다. 인증 만료, 권한 거부, 항목 없음, 충돌, 일시 장애를 구분한다.
- 자격 증명은 호스트의 보안 저장소 참조로 관리하고 플러그인 설명 파일이나 로그에 기록하지 않는다.

### 4.2. 배포와 로드

```text
plugins/
 ├─ WebDAV/
 │   ├─ plugin.json
 │   ├─ MYSync.Provider.WebDAV.dll
 │   └─ 의존 라이브러리
 └─ GoogleDrive/
     ├─ plugin.json
     ├─ MYSync.Provider.GoogleDrive.dll
     └─ 의존 라이브러리
```

설명 파일에는 고유 ID, 표시명, 플러그인 버전, 지원 계약 버전 범위, 진입 어셈블리와 클래스, 런타임·아키텍처 요구사항을 기록한다. 진입 파일은 해당 플러그인 폴더 내부로 제한한다.

첫 버전의 설치 흐름은 폴더에 플러그인 추가 → 앱 재시작 → 사용 가능한 클라우드 목록 표시로 한다. 앱 시작 시 설명 파일, 중복 ID, 계약 호환성, 의존성, 진입 형식을 검증한다. 오류가 있는 플러그인은 등록하지 않고 이유를 표시한다.

Provider별 의존성 로드 범위를 분리하되 Provider.Abstractions 계약 어셈블리는 호스트와 공유하도록 설계한다. 구체적인 로더 구현은 .NET의 어셈블리 로드 기능을 검토해 확정한다. DLL 분리는 보안 격리가 아니므로 첫 버전은 직접 개발하거나 신뢰하는 플러그인을 대상으로 한다.

### 4.3. 버전·업데이트·장애 처리

- 계약 버전을 플러그인 제품 버전과 별도로 관리하고, 호환되지 않는 계약은 실행 전에 거부한다.
- 계정과 동기화 쌍에는 안정적인 Provider ID를 저장한다. 업데이트 후에도 같은 계정과 기준 상태를 연결한다.
- 플러그인별 설정과 커서에는 스키마 버전을 두고, 호환되지 않는 상태는 명시적으로 마이그레이션하거나 재검사한다.
- 업데이트는 관련 전송을 중단하고 앱을 종료한 뒤 교체·재시작하는 방식으로 한다. 실행 중 DLL 교체는 지원하지 않는다.
- 플러그인이 누락되거나 로드에 실패하면 해당 동기화 쌍을 사용 불가 상태로 유지한다. 계정·기준 상태·작업 큐를 삭제하거나 원격 항목 삭제로 해석하지 않는다.
- 일반적인 초기화·작업 오류는 해당 Provider 또는 동기화 쌍에 표시한다. 같은 프로세스에서 실행하는 첫 버전은 프로세스 수준 장애까지 격리한다고 보장하지 않는다.
- 외부 개발자용 프로세스 격리, 온라인 플러그인 배포, 실행 중 설치·교체는 후속 범위로 둔다.

## 5. 사용자 흐름

1. 로드된 Provider 목록에서 WebDAV, Google Drive 또는 추가 Provider를 선택하고 계정을 연결한다.
2. Windows 폴더 선택 창에서 로컬 폴더를 선택한다.
3. 원격 폴더 탐색 화면에서 대상 폴더를 선택한다.
4. 앱이 접근 권한, 경로 중첩, 기존 동기화 쌍과의 충돌을 검사한다.
5. 최초 비교 결과와 예상 작업을 표시한다.
6. 동기화를 시작하고 전송 상태·충돌·오류를 표시한다.
7. 이후 변경을 감지해 자동 동기화한다.

동기화 쌍 목록에는 계정, 로컬·원격 경로, 실행 상태, 마지막 성공 시각, 대기 작업 수를 표시한다. 진행 화면에는 현재 파일, 전송량, 속도, 실패 원인과 재시도 상태를 표시한다.

## 6. 동기화 정책

| 상황 | 처리 기준 |
|---|---|
| 최초 연결에서 한쪽에만 존재 | 다른 쪽으로 복사 |
| 최초 연결에서 동일 경로·동일 내용 | 전송 없이 기준 상태 기록 |
| 최초 연결에서 동일 경로·다른 내용 | 양쪽 내용을 충돌 사본으로 보존 |
| 한쪽에서 추가 | 반대쪽에 생성 |
| 한쪽에서 수정 | 반대쪽 변경 여부를 확인한 후 갱신 |
| 양쪽에서 수정 | 두 버전 보존 및 충돌 표시 |
| 한쪽에서 삭제 | 이전 동기화 이력과 상대쪽 변경 여부 확인 후 반영 |
| 한쪽 삭제·다른 쪽 수정 | 자동 파기하지 않고 수정본 보존 및 충돌 표시 |
| 네트워크 단절·인증 실패 | 실패 상태로 기록하고 삭제 판정 중단 |
| 앱 재시작 | 미완료 큐와 실제 상태를 대조한 뒤 재개 |

로컬 현재 상태, 원격 현재 상태, 마지막 성공 상태의 3자 비교로 작업을 결정한다. 수정 시각만으로 최신 파일을 판단하지 않는다. 크기·버전·해시 등 Provider가 제공하는 정보를 조합하고, 내용을 검증할 수 없으면 동일하다고 단정하지 않는다.

폴더 삭제는 하위 항목의 변경 여부까지 확인한 후 처리한다. 연결 실패, 목록 조회 실패, 권한 오류, 불완전한 페이지 조회를 빈 폴더로 취급하지 않는다. 원격 루트나 로컬 루트가 사라지면 자동 대량 삭제 대신 해당 쌍을 오류 상태로 중단한다.

이동·이름 변경은 식별 가능한 경우 이동으로 처리한다. 식별이 불확실하면 복사·삭제로 처리하되 복사 성공을 확인하기 전에 원본을 삭제하지 않는다.

## 7. 상태 저장 및 복구

SQLite는 동기화 대상 폴더 밖의 앱 데이터 디렉터리에 저장한다.

| 데이터 | 주요 항목 |
|---|---|
| Accounts | 안정적인 Provider ID, 설정 스키마 버전, 계정 표시명, 비밀 저장소 참조 |
| SyncPairs | 로컬 루트, 원격 루트 ID/경로, 활성·일시정지 상태 |
| ItemStates | 상대 경로, 원격 ID, 유형, 크기, 버전, 마지막 성공 기준 |
| Jobs | 작업 종류, 대상, 상태, 재시도 횟수, 예상 이전 버전 |
| ProviderCursors | 변경 추적 커서와 재검사 상태 |
| Conflicts | 충돌 유형, 양쪽 버전, 보존 사본 위치 |

메모리 채널은 실행 조율에만 사용하고 작업의 원본 상태는 DB에 유지한다. 작업은 대기 → 실행 → 완료 또는 재시도·충돌·실패 상태로 전이한다. 원격 작업 성공 직후 앱이 종료되어도 재시도 전에 실제 상태를 확인해 중복 생성이나 덮어쓰기를 방지한다.

다운로드는 임시 파일에 기록하고 검증 후 최종 경로로 교체한다. 업로드 중 로컬 파일이 변경되었으면 완료 기준을 확정하지 않고 다시 비교한다. 전송 단위의 이어받기는 Provider와 서버 지원에 따라 구현하며, 미지원 환경에서는 안전하게 파일 단위로 재시작한다.

## 8. Provider별 구현 고려사항

### WebDAV

- 서버 주소와 인증 정보를 입력받고 연결·읽기·쓰기 권한을 검증한다.
- 폴더 조회와 변경 비교를 주기적으로 수행하는 방식을 기본으로 한다.
- 경로 인코딩, 서버별 메타데이터 차이, 이동·조건부 쓰기 지원을 검증한다.
- ETag를 파일 내용 해시로 단정하지 않는다.
- 대량 목록 조회와 일부 응답 실패 시 삭제를 확정하지 않는다.

### Google Drive

- 데스크톱 OAuth 흐름과 토큰 갱신을 구현한다.
- 원격 루트와 파일은 경로 문자열뿐 아니라 원격 ID로 추적한다.
- 최초 전체 조회 후 변경 추적을 적용하고, 커서가 유효하지 않으면 재검사한다.
- 임의의 기존 폴더 선택에 필요한 권한 범위와 배포 시 검증 요건을 구현 전에 확인한다.
- 같은 이름의 항목, Google 문서 형식, 바로가기, 공유 드라이브의 매핑 정책을 별도로 정의한다.

이 절의 API 세부 사항은 구현 전 공식 문서와 실제 연결 대상으로 확인할 검증 항목이다.

## 9. 전체 폴더 동기화의 예외 처리

일반 파일과 하위 폴더를 재귀적으로 모두 조회한다. 처리 불가능한 항목을 조용히 건너뛰거나 완료로 표시하지 않는다.

- 빈 폴더도 동기화한다.
- 숨김 파일을 임의로 제외하지 않는다. 접근할 수 없는 항목은 이유를 표시한다.
- Windows에서 표현할 수 없는 이름, 대소문자 충돌, 경로 길이 문제는 명시적으로 보고한다.
- 심볼릭 링크·정션은 루트 밖 탐색이나 순환이 발생하지 않도록 기본적으로 추적하지 않고 미지원 항목으로 표시한다.
- 잠긴 파일은 재시도하며, 다른 파일 작업은 계속할 수 있도록 한다.
- 앱의 임시 파일은 사용자 파일과 구분하고 자체 변경의 무한 동기화 루프를 방지한다.
- Google 문서 등 일반 바이너리 파일과 다른 항목은 내보내기 또는 별도 처리 정책이 확정되기 전까지 미해결 항목으로 표시한다.

모든 항목이 처리되었을 때만 전체 동기화 완료로 표시한다. 예외가 남으면 부분 완료 또는 주의 상태로 표시한다.

## 10. 개발 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1. 기반 구성 | 솔루션 분리, WPF, DB, Provider.Abstractions, PluginHost | 설정 저장·복원 및 샘플 플러그인 검색·로드·호환성 거부 검증 |
| 2. 엔진 구현 | 전체 스캔, 3자 비교, 영속 큐, 충돌 정책 | 가짜 Provider와 임시 폴더로 추가·수정·삭제 검증 |
| 3. WebDAV 플러그인 | 인증, 원격 탐색, 기본 파일 작업 | 공통 계약만으로 실제 서버에서 폴더 전체 왕복 동기화 |
| 4. Google Drive 플러그인 | OAuth, 원격 탐색, 파일 ID, 변경 추적 | 엔진의 Provider별 분기 없이 실제 계정에서 동일 시나리오 통과 |
| 5. 상시 동기화 | 파일 감지, 재검사, 재시도, 트레이, 일시정지 | 단절·재시작·이벤트 누락 후 수렴 |
| 6. 배포 준비 | 설치·업데이트 방식 결정, 로그, 성능 점검 | 깨끗한 Windows 환경에서 설치·실행·복구 검증 |

인원, 지원 Windows 버전, 대표 데이터 규모, 배포 방식이 정해지지 않았으므로 일정은 아직 산정하지 않는다.

## 11. 검증 계획

- 엔진 테스트: 최초 병합, 양쪽 수정, 수정·삭제 충돌, 폴더 삭제, 같은 이름의 파일·폴더 충돌.
- 플러그인 검증: 새 샘플 DLL을 엔진 재빌드 없이 추가하고 재시작 후 목록 표시·계정 연결·기본 작업까지 확인한다. 계약 불일치, 중복 ID, 의존성 누락, 초기화 실패, 제거·업데이트 후 기존 동기화 쌍 보존도 검증한다.
- Provider 계약 테스트: 동일한 재사용 테스트 묶음을 모든 Provider에 적용하고, 선택 기능 미지원 시 대체 동작과 오류 분류를 검증한다.
- Provider 통합 테스트: 폴더 생성, 목록 조회, 업로드·다운로드, 이동, 삭제, 인증 만료와 권한 오류.
- 복구 테스트: 전송 도중 종료, 원격 성공 직후 종료, 연결 단절, 디스크 부족, DB의 미완료 작업 재실행.
- 파일 시스템 테스트: 한글·공백·특수문자, 빈 폴더, 잠긴 파일, 대소문자 충돌, 긴 경로.
- 누락 복구 테스트: 파일 감지 이벤트 없이 변경한 후 재검사만으로 동일 상태에 도달하는지 확인.
- 삭제 안전성 테스트: 원격 목록 조회 실패나 루트 접근 실패가 반대쪽 삭제로 이어지지 않는지 확인.
- 실데이터 검증: 격리된 테스트 폴더에서 파일 수·상대 경로·내용을 비교하며 충돌 사본까지 확인.
- 성능 측정: 대표 파일 개수와 크기를 정한 뒤 최초 스캔, 증분 동기화, 메모리 사용량과 전송량 측정.

## 12. 첫 버전 범위 및 후속 기능

첫 버전은 DLL 플러그인 검색·검증·로드, 동일 규격의 WebDAV·Google Drive 플러그인, 계정 연결, 폴더 쌍 설정, 재귀 양방향 동기화, 삭제 반영, 충돌 보존, 일시정지·재개, 재시도, 진행 상태, 트레이를 포함한다.

변경 블록만 전송하는 최적화, 탐색기 온라인 전용 파일, 로그아웃 중 서비스 실행, 클라우드 간 직접 동기화, 자체 서버, 종단간 암호화는 후속 범위다. 자격 증명 보호와 전송 보안은 첫 버전에도 포함한다.

구현 전에 결정할 항목:

1. 최소 지원 Windows 버전과 CPU 아키텍처.
2. Google 문서·바로가기·공유 드라이브의 지원 범위.
3. 검증 대상 WebDAV 서버와 인증 방식.
4. 삭제 복구·보존 기간 및 대량 삭제 처리 UX.
5. 대표 파일 개수·파일 크기와 배포·자동 업데이트 방식.
