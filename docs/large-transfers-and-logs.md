# 대용량 전송·파일 제어·로그 (2026-09-08)

## 파일 크기 제한

MYSync의 Google Drive 5 MiB 제한을 제거했다. 작은 파일은 기존 multipart, 큰 파일은 Google resumable 세션과 최대 8 MiB 청크를 사용한다. 파일 전체는 임시 디스크에 검증용으로 보관하며 메모리에 통째로 올리지 않는다. 계정 저장 용량·서버 제한·로컬 임시 공간은 여전히 적용된다.

청크 범위와 서버 확인 응답을 검사하고 세션 URL의 HTTPS·Google 호스트를 검증한다. 기존 파일 교체는 조건부 요청과 마지막 청크 전 버전 검사, 게시 후 전체 내용 해시 검증을 유지한다. 앱 재시작·불확실한 네트워크 중단 시 세션 오프셋을 저장해 이어 쓰지는 않으며, 양쪽을 다시 검사하고 필요한 파일을 다시 전송한다. [Google 업로드 공식 문서](https://developers.google.com/workspace/drive/api/guides/manage-uploads)

## 전송 목록 제어

큐의 대기 항목도 전송 화면에 표시한다. 선택 중지·선택 취소는 해당 파일(폴더면 하위 작업 포함)을 이번 앱 실행 동안 보류하고 전송 요청을 취소한다. 원본·이미 게시된 파일을 삭제하거나 되돌리지 않는다. 다른 작업은 계속 처리하며, 전체 동기화 완료 판정은 보류 파일을 재개한 뒤 최종 검사로 결정한다.

재개는 보류를 해제하고 다시 검사한다. 자동 감시는 다음 검사 신호로, 수동 창은 다음 실행으로 이어진다. 앱 재시작 시 일시 보류는 초기화된다. 영구적으로 동기화에서 빼려면 **동기화에서 제외**를 사용한다. 이 작업은 연결 감시를 중지하고 정확한 루트 상대 경로를 제외 규칙에 저장하므로 자동 시작으로 나머지 작업을 이어간다. 수동 창에도 파일 중지·취소·재개·제외 버튼이 있다.

이미 반영되어 검증 중인 작업은 취소로 되돌리지 않는다. 네트워크 요청이 취소될 때 서버 반영 여부가 불확실하면 재검사 대상으로 남긴다.

## 로그 및 설정

실행파일 옆 **,log/sync.jsonl**에 전송 상태·누적 처리 바이트·작업 ID·오류 분류·HTTP 상태를 JSONL 형식으로 기록한다. URL·인증 헤더·토큰·원문 예외 메시지는 기록하지 않는다. 정확한 파일별 오류 설명은 앱의 오류/복구 화면에서 확인한다.

설정 → 로그·진단에서 1~1024 MiB를 지정한다(기본 10 MiB). 한도를 넘기기 전에 오래된 완전한 행부터 제거하고 최신 행을 추가한다. 한도 축소도 다음 기록에 적용된다. 로그 파일이 잠겼거나 폴더에 쓸 수 없는 경우 전송 결과를 바꾸지 않는다. 이전 버전의 사용자 데이터 폴더 아래 일자별 로그는 별도로 유지한다.

환경 설정은 좌측 탐색과 우측 상세 패널, 빨간 주요 버튼으로 개편했다. 일반 / 동기화·전송 / 로그·진단 / 앱 정보로 구분한다. [MEGAsync 저장소](https://github.com/meganz/MEGAsync)를 참고했으며 MYSync 기능에 맞게 구성했다.

## 검증

9 MiB 초과 파일의 2청크 업로드·다운로드, 기존 Google/WebDAV 보호 검증, 진행 파일 취소·대기 파일 보류·다른 파일 계속 실행·재개, 로그 크기 상한·오래된 행 제거·JSON 무결성·한도 축소를 자동 검증했다. 설정 화면은 WPF 렌더링으로 확인했다. 실제 Google/NAS 서버에서 대용량 전송·중단 테스트는 별도다.
