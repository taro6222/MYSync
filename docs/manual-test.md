# 수동 테스트 안내

## 전송 성능 업데이트 (2026-09-08)

파일별 전송·검증 완료를 즉시 표시하고 전체 비교는 별도로 진행한다. Google 체크섬·버전별 검증 결과 재사용, 병렬 검사, 자동 실행의 중복 전체 검사 제거, 스트리밍 해시, 로그 정리 비용 감소를 적용했다. [성능 동작·검증](transfer-performance.md)을 참고한다.


## 파일 오류 해결 업데이트 (2026-09-08)

전송 화면에 오류 해결·이번만 제외를 추가했다. 해결 창에서 재검사, 방향 선택 후 선택 파일 전송, 원본 사본 보존, 이번 실행 제외를 제공한다. [사용 안내](file-error-actions.md)를 참고한다.


## 사이드바·동기화 지속성 업데이트 (2026-09-08)

전체 메뉴를 사이드바로 통합했다. Google ETag 호환 덮어쓰기, 최대 3개 파일 병렬 전송, 정상 파일별 비교 기준 저장, 오류 이후 새 변경 처리와 구버전 Applied 기록 복원을 추가했다. [동작 및 검증](sidebar-and-concurrent-sync.md)을 참고한다. 아래 과거의 순차 실행·오류 시 확인 대기 고정 설명보다 이 업데이트를 우선한다.


## 대용량·파일 제어·설정 개편 (2026-09-08)

Google 파일 크기 제한을 제거하고 대용량 청크 업로드를 추가했다. 진행·대기 파일의 중지/취소/재개/제외, 실행파일 옆 ,log 폴더의 용량 제한 순환 로그, 카테고리별 설정 UI를 제공한다. [동작·제한·검증 안내](large-transfers-and-logs.md)가 아래 과거 5 MiB 제한 및 일자별 로그 설명보다 우선한다.


## 오류 알림·개별 정책·OAuth 배포 업데이트 (2026-09-08)

트레이 오류 알림 클릭 시 해당 오류 페이지로 이동한다. 연결별 파일·폴더 제외와 합산 전송 속도(KiB/s, 0=무제한)를 설정할 수 있다. Google 설정은 DLL 내부 리소스로 전환해 배포 폴더에 oauth-client.json을 복사하지 않는다. 내장 리소스는 추출 가능하므로 비밀 보장으로 간주하지 않는다. [설정 및 테스트](sync-options-and-alerts.md), [OAuth 배포와 보안 한계](oauth-distribution.md)를 참고한다. 아래 구버전 설명과 다르면 이 업데이트를 우선한다.


## 실행

`MYSync.Desktop.exe`를 실행하세요. Windows x64용 단일 EXE에 .NET 런타임이 포함됩니다. 다른 위치로 옮길 때는 외부 Provider가 있는 plugins 폴더도 함께 복사하세요.

## 현재 테스트할 기능

1. 동기화 추가 탭에서 Sample을 선택하고 로컬 폴더와 샘플 원격 폴더를 선택한 후 동기화 쌍 저장.
2. 앱을 종료하고 다시 실행해서 저장한 쌍이 나타나는지 확인.
3. WebDAV를 선택하고 계정 연결 버튼으로 서버 주소, 포트(기본 443), 사용자 이름, 비밀번호 또는 앱 비밀번호 입력. 예: nas.example.com/webdav/ + 5006. 포트 입력값이 주소에 포함된 포트보다 우선합니다.
4. 원격 폴더 목록에서 선택 폴더 열기와 연결 루트로 이동 확인.
5. 틀린 인증이나 접근 불가능한 주소에서 오류 안내 확인.
6. WebDAV 연결 성공 후 로컬·원격 폴더를 선택하고 폴더 연결 저장. 앱 재시작 후 목록이 복원되는지 확인.
7. 동기화 추가에서 WebDAV와 저장된 계정을 선택한 후 ‘저장 계정 연결’로 비밀번호 없이 다시 연결.
8. 여러 계정 사이를 전환하면 이전 폴더 목록이 비워지고 재연결 후 해당 계정의 폴더만 표시되는지 확인.
9. 별도의 테스트용 로컬·원격 폴더에 파일을 넣고 동기화 목록의 ‘검사·실행’ → ‘변경 검사’에서 예상 작업 확인.
10. ‘표시된 작업 실행’ 후 파일 내용과 양쪽 폴더를 비교. 파일 수정·파일 삭제도 검사와 실행을 반복해 확인.
11. 실행 중 ‘중단’을 누른 뒤 다시 검사하여 미완료 작업을 재개. 원격 폴더 삭제는 현재 중단되는 것이 정상이다.
12. 별도의 테스트 폴더 쌍에서 ‘자동 시작’을 누르고 로컬 파일을 추가·수정해 약 2초 후 변경 검사가 실행되는지 확인.
13. 원격에 파일을 추가한 뒤 다음 5분 주기 검사에서 다운로드되는지 확인.
14. ‘일시정지’ 후 변경이 전송되지 않는지 확인하고 다시 시작. 앱 재실행 시 자동 실행 중이던 항목만 다시 시작하는지 확인.
15. 인증 실패나 충돌이 있으면 자동 감시가 일시정지되고 하단에 오류가 나타나는지 확인.
16. X 버튼으로 창을 닫아도 트레이 아이콘이 남고 자동 감시가 계속되는지 확인. 트레이 두 번 클릭으로 다시 열기.
17. 트레이 ‘모두 일시정지’와 ‘종료’를 확인. EXE를 두 번 실행했을 때 기존 창이 표시되는지 확인.
18. 설정에서 로그인 시 실행을 켜고 다음 Windows 로그인에서 트레이로 시작되는지 확인. 테스트 후 필요하면 설정을 끄기.
19. 같은 파일을 양쪽에서 다르게 고쳐 충돌을 만든 뒤 ‘검사·실행’으로 충돌 사본이 양쪽에 생기는지 확인. 이어서 ‘충돌·복구’를 열고 ‘연결·현재 상태 검사’ 후 ‘로컬 파일 우선’ 또는 ‘원격 파일 우선’을 선택. 다시 ‘검사·실행’에서 재개해 선택한 내용이 반대쪽에 반영되고 사본 두 개가 남는지 확인.
20. ‘충돌·복구’의 복구 기록 탭에서 교체·삭제 기록의 판정과 보관 경로 확인. ‘보관본을 다른 위치로 복원’으로 동기화 폴더 밖에 저장해 내용 비교. 동기화 폴더 안을 선택하면 거부되는 것이 정상이다.
21. 기록을 ‘확인 처리’한 뒤 `.MYSync-recovery\{pairId}\resolved`에 기록과 보관본이 남는지, 그리고 차단되어 있던 검사가 다시 동작하는지 확인.
22. 전송 탭에서 수동 실행·자동 감시 중 상태, 작업 수(예: 2/5), 전송량, 현재 항목이 갱신되는지 확인. 자동 감시를 일시정지하면 해당 줄이 ‘대기’로 돌아오는지 확인.
23. 저장된 계정에서 ‘이름 변경’ 후 목록 표시가 바뀌고, ‘저장 계정 연결’이 여전히 성공하는지 확인.
24. ‘인증 정보 수정’으로 비밀번호를 다시 입력해 연결되는지, 틀린 값으로는 실패하고 기존 계정이 유지되는지 확인. ‘계정 삭제’는 그 계정을 쓰는 동기화 항목이 있으면 거부되고, 항목을 지운 뒤에는 삭제되는지 확인.

25. 동기화 중 네트워크를 잠시 끊었다가 복구해 하단 안내에 재시도 문구가 뜨고 자동으로 이어지는지 확인. 계속 끊어두면 몇 차례 재시도 후 감시가 멈추고 확인 요청이 뜨는지 확인.
26. 잘못된 비밀번호로 저장 계정을 바꾼 뒤 자동 시작하면 재시도 없이 즉시 멈추고 인증 오류가 표시되는지 확인.
27. 파일이 많은 폴더에서 두 번째 검사가 첫 검사보다 빠른지 확인. 파일을 수정하면 그 파일만 다시 읽고 변경이 반영되는지 확인.

28. 동기화 폴더 안에 바로 가기(정션·심볼릭 링크)를 만들고 검사하면, 전체가 멈추지 않고 그 항목만 '미지원 항목'으로 표시되며 나머지 파일은 정상 동기화되는지 확인.
29. 원격에 `aux.txt`처럼 Windows에서 쓸 수 없는 이름의 파일을 두고 검사하면 오류가 아니라 미지원 항목으로 보고되고, 로컬에 만들어지지 않는지 확인. 자동 감시 상태 줄에 '미지원 항목 N개'가 나오는지도 확인.


30. 전송 실패 후 앱을 재시작하고 ‘충돌·복구’에서 마지막 실패 사유·분류·시각이 유지되는지 확인. `%LOCALAPPDATA%/MYSync/logs`에서 해당 작업 ID의 HTTP 응답 코드와 강한 헤더 ETag 유무를 확인. 로그에는 비밀번호·인증 헤더·URL이 없어야 한다. Synology ETag 오류 자체는 아직 수정 전이다.

31. Google Drive 연결·탐색은 [설정 안내](google-drive-setup.md)에 따라 데스크톱 OAuth 클라이언트를 준비한 후 테스트한다. 브라우저 로그인, 내 드라이브 폴더 탐색, 저장 계정 재연결을 확인한다. 현재 Google 동기화 쌍 저장은 거부되는 것이 정상이다.

## 현재 제한

Google 전송 업데이트: 새 버전에서 Google 다시 로그인으로 파일 관리 권한을 승인한 뒤 테스트 폴더 쌍을 저장할 수 있다. 5 MiB 이하 파일의 업/다운로드·수정·휴지통 이동을 검사·실행에서 확인한다. 자세한 내용은 [google-drive-transfer.md](google-drive-transfer.md)를 따른다. 이전의 Google 탐색 전용·쌍 저장 차단 설명은 초기 단계 기록이다.

ETag 재테스트: 새 테스트 폴더에서 최초 업로드·교체·삭제를 수행하고 로그의 `webdav.resource-etag`와 `webdav.response`를 비교하세요. GET 헤더 ETag가 없어도 PROPFIND에 강한 ETag가 있으면 전송할 수 있습니다. 실제 Synology 검증은 아직 남아 있으며, 이전 잔류 `.mysync-upload-` 파일을 자동으로 정리하지 않습니다.

- 수동 실행은 실제 파일을 추가·수정·삭제합니다. 작업 목록의 DeleteLocal·DeleteRemote는 삭제 전파입니다. 먼저 별도의 테스트 폴더에서 확인하세요.
- 계정은 현재 Windows 사용자에 묶어 암호화합니다. 다른 사용자·PC로 DB를 복사하면 복호화하지 못할 수 있습니다. 자동 접속 대신 저장 계정 연결 버튼을 사용합니다.
- WebDAV는 HTTPS + Basic 인증만 지원합니다. 자동 리디렉션을 따라가지 않으므로 최종 WebDAV 폴더 URL을 입력해야 합니다.
- Google Drive는 연결·폴더 탐색만 지원하며 전송은 구현 전입니다. 충돌·복구 확인 화면은 파일 충돌만 처리하며 폴더·유형 충돌은 지원하지 않습니다.
- 링크·정션과 Windows에서 쓸 수 없는 이름은 동기화하지 않고 목록에만 표시합니다. 개별 항목을 무시하거나 강제로 처리하는 기능은 없습니다. 기본적으로 X 버튼은 트레이로 숨기므로 테스트를 마칠 때 트레이의 종료를 사용하세요.
- 원격 파일 검사에 전체 다운로드가 필요합니다. 강한 ETag와 조건부 MOVE를 지원하는 서버가 필요하며 원격 폴더 삭제는 아직 지원하지 않습니다. 자동 시작은 파일 삭제도 자동 반영합니다.
- 샘플 설정은 %LOCALAPPDATA%/MYSync/settings.db에 저장합니다.
- 비밀번호나 인증 헤더를 테스트 보고에 포함하지 마세요. 문제가 있으면 수행 순서와 화면의 오류 문구를 알려주세요.
